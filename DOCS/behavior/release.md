# Release automation behavior

## BUG-RELEASE-001: Use automatic App Store signing during export
- Type: Bug
- Status: Resolved
- Scope: App Store exports produced by `bundle exec fastlane ios release`, including the main app and Share extension.
- Observed behavior / Reproduction: The archive succeeds, but export fails because the lane pins the app to a provisioning-profile UUID that is not installed, provides no profile mapping for the Share extension's App Groups entitlement, and Xcode reports no matching Apple Distribution certificate with a private key for the team.
- Goal / Acceptance criteria: Export with Xcode automatic signing so the app and extension can use current App Store provisioning profiles instead of a stale, hard-coded profile UUID.
- Expected behavior and invariants: The lane requests an App Store Connect export and allows Xcode to manage signing for both bundle identifiers. The existing App Groups entitlement remains part of the extension's signed profile. App Store upload starts only after export succeeds.
- Enforcement boundary: `fastlane/Fastfile`, Xcode automatic signing settings, target bundle identifiers and entitlements.
- Current behavior: The release lane requests an App Store export with Fastlane 2.240.1's supported `app-store` method, enables Xcode provisioning updates for archive and export, and uses automatic signing without a pinned profile UUID. Xcode accepts the method while reporting that it is deprecated. The lane delegates profile selection and updates to Xcode for the main app and Share extension using each target's configured bundle identifier and entitlements. It authenticates App Store Connect operations with the configured API key, skips the unsupported In-App Purchase portion of API-key precheck, and reaches upload only after `gym` has produced the export. It uploads only the configured English What's New note and leaves other App Store metadata untouched. The `submit_uploaded_build` lane can submit the existing IPA after an upload-stage interruption without uploading the binary again.
- Regression coverage: No automated Fastlane lane test or XCTest seam covers export signing options or verifies that the selected marketing version has an open App Store Connect pre-release train.
- Known limitations: Export still depends on Xcode being signed in to the Apple Developer team, with automatic signing allowed for both bundle identifiers and the App Groups capability. The team must permit cloud-managed signing or provide an Apple Distribution certificate with its private key. The lane authenticates upload and submission with the App Store Connect API key identified by the three `APP_STORE_CONNECT_API_KEY_*` variables in the ignored repository-root `.env`; its `.p8` file belongs in an ignored location such as `fastlane/`. A Developer role can upload builds, while App Review submission requires Account Holder, Admin, or App Manager access. App Store Connect closes a pre-release train after approval, so the app and Share extension marketing version must be a new, higher version with an open train; the lane increments only the build number and does not select or validate a marketing version. Fastlane's API-key precheck does not inspect In-App Purchases. The lane combines export with App Review submission and automatic release; it is not an export-only workflow.
